# Prism v2.2 local release runbook

Prism v2.2 runs several private Prisms, each with its own conversation, memory, Teams scope,
monitoring schedule, updates, and approvals. Monitoring only reads Teams. Every Teams message is
still an approval-gated draft that is sent once, from your connected account, after you click
**Approve and send**. Nothing runs while the local API is stopped, and browser alerts appear only
while a Prism page is open.

## Set up from a clean checkout

```bash
make setup            # Python 3.11 venv and dependencies
cp .env.example .env  # then fill in the values below
make migrate
make dev
```

Required `.env` values (never commit them):

| Setting | Purpose |
| --- | --- |
| `PRISM_V21_ENABLED=true`, `PRISM_V22_ENABLED=true` | Turn the features on. |
| `PRISM_V22_SINGLE_EXECUTIVE_MODE=false` | Allows more than one Prism. |
| `OPERATOR_API_TOKEN` | Required for any non-development setup; guards every `/api/` route. |
| `PRISM_V22_SCHEDULER_ENABLED=true` | Runs scheduled, continuous, and event-driven monitoring. |
| Azure OpenAI or OpenAI settings | The model provider. Optional for rule-based monitoring. |
| Microsoft app settings | Delegated sign-in; see the main README. |

No public tunnel is needed for v2.2 monitoring. It polls Teams through delegated Graph reads.

## Upgrade from v2.1

1. Back up the database (see below).
2. `make migrate`. Migrations are additive; v2.1 tables and data are untouched.
3. Start the app, then adopt your original conversation as a Prism:
   `python scripts/prism_admin.py migrate-v21`
   (or `POST /api/v2/prisms/migrate-legacy`). It is safe to repeat.
4. Open the new **Executive Assistant** Prism. Your history, evidence, preferences, plans,
   approvals, executions, and deep links are unchanged; the thread only gained an owner.
5. The migrated Prism starts with a minimal confirmed agreement and **Manual only** monitoring.
   Open **⋯ → Status & tuning**, review it, and click **I've reviewed this Prism**. Until then no
   automatic run starts. Then choose a schedule in **⋯ → Monitoring schedule**.

## Day-to-day setup per Prism

1. **Create Prism** and answer the onboarding questions in the chat; confirm the working agreement.
2. **⋯ → Teams monitoring scope**: all accessible chats (default) or up to the chats you choose.
   An exclusion applies before any message reaches a model.
3. **⋯ → Monitoring schedule**: Manual only, Daily, Continuous, or Event-driven. Continuous and
   scheduled modes need `PRISM_V22_SCHEDULER_ENABLED=true` and a running server.
4. **⋯ → Notifications**: opt in, pick an urgency threshold, and allow the browser permission when
   asked. If it is denied or unsupported, updates still appear in the conversation.
5. **⋯ → Status & tuning**: see why a Prism is quiet, delayed, or failing; mute signals you
   confirm are noisy; adjust its run and model budgets.

## Microsoft scope

Delegated permissions are the ones in the main README, including Teams chat read and write.
"All chats" means every chat your connected account can already read; it never widens Microsoft
permissions. Reading a chat never authorizes writing to it. Each destination is shown on its own
approval card, and the exact approved text is what is sent.

## Provider and operating budgets

Safe defaults, all overridable in `.env`, and per Prism in **Status & tuning**:

| Setting | Default | Meaning |
| --- | --- | --- |
| `V22_MAX_RUNS_PER_DAY` | 400 | Automatic runs per Prism per UTC day. |
| `V22_MAX_MODEL_CALLS_PER_DAY` | 100 | Model assessments per Prism per day; then rules only. |
| `V22_MAX_CONSECUTIVE_FAILURES` | 3 | Failed runs in a row before a pause. |
| `V22_FAILURE_BACKOFF_MINUTES` | 30 | Length of that pause. Manual runs are never blocked. |
| `V22_EVENT_RETENTION_DAYS` | 30 | Raw Teams activity is deleted after this; updates and approvals stay. |
| `V22_PRESENCE_TTL_SECONDS` | 120 | How long an open page counts as present for alerts. |
| `V22_INCIDENT_WINDOW_HOURS` | 24 | Window for grouping later messages into one incident. |

`V22_SIGNAL_MODEL_ENABLED` is off by default; without it Prism uses explicit-wording rules.

## Recovery commands

```bash
python scripts/prism_admin.py status                          # counts of stuck work
python scripts/prism_admin.py recover-runs                    # re-queue runs whose lease expired
python scripts/prism_admin.py recover-runs --cancel-queued-older-than 60 --force-running
python scripts/prism_admin.py recover-notifications           # close claims whose page vanished
python scripts/prism_admin.py reset-cursors [--prism-id UUID] # clear degraded Teams cursors
python scripts/prism_admin.py compact                         # run retention now
```

They print counts only, are safe to repeat, and never read Teams or send anything. If Ctrl+C will
not stop the server, a scheduler cycle is mid-read; a second Ctrl+C or `kill -9` is safe, because
runs are lease-recovered on the next start.

## Roll back to v2.1

Set `PRISM_V22_ENABLED=false` and restart. Every `/api/v2/prisms` route returns 404, the v2.1
Agent keeps working, and nothing is deleted. The migrated conversation is still the v2.1
conversation, so no history is lost or forked. Turning v2.2 back on restores all Prisms.

## Backup and restore

```bash
pg_dump "$DATABASE_URL" -Fc -f prism-backup.dump     # before any upgrade
pg_restore --clean --if-exists -d "$DATABASE_URL" prism-backup.dump
```

Back up before `make migrate`. Credentials are encrypted in the database; keep
`MICROSOFT_TOKEN_ENCRYPTION_KEY` with the backup, or stored tokens cannot be read.

## Safe live test (one read, one send)

1. Use a dedicated development tenant or a Teams chat with yourself.
2. Confirm the connected Microsoft account is yours.
3. Scope a test Prism to that one chat, post "Prod is down, checkout returning 500s", and use
   **⋯ → Refresh Teams activity**.
4. Check the update card and that one browser alert appears. Open **Why this is grouped**.
5. **Prepare a Teams draft**, edit it to an obvious test message, and click **Approve and send**
   once. Confirm Teams shows it once from your account and Prism shows `Sent`.
6. In the database, check the approval, execution, and incident audit rows; in **Status &
   tuning**, check budgets and the 24-hour counts. No message text appears in the counts.

## Release gate

```bash
make release-check   # lint, format, types, unit tests, PostgreSQL integration, secrets, audit
make test-e2e        # browser journeys (needs Google Chrome)
```

Known limits: raw Teams activity is kept only for the retention window; alerts need an open page;
model token use is tracked as calls per Prism, not tokens per Prism; one real-Microsoft smoke
test and a keyboard and screen-reader pass remain manual.
