# v2.4 runbook: every Prism has its own computer

## Turn it on
1. Docker Desktop must be running **on the machine that runs the engine's worker**.
2. Engine `.env`: `PRISM_BRIDGE_URL`, `PRISM_BRIDGE_SECRET` (same value as Prism's `WORK_BRIDGE_SECRET`; needed only for Teams tools). Optional: `COMPUTER_IMAGE` (pin a tag). Keep `COMPUTER_ALLOW_LOCAL_SITES=false` outside explicit local development.
3. Stop the engine worker, then apply migrations: Prism `make migrate`; engine `.venv/bin/alembic upgrade head`.
4. Restart the engine API **and its worker**, then Prism (`PRISM_V24_ENABLED=true`). Stopping the old worker before the lease migration prevents mixed-version claims.
5. `python scripts/prism_admin.py work-check` must print `"ok": true` (engine reachable, a worker online, Docker answering).

## Operate
- `python scripts/prism_admin.py computers list` shows each Prism's computer (missing / stopped / running).
- `computers stop [--key prism-xxxxxxxx]` stops one or all (browser profiles are kept).
- `computers reset [--key ...]` deletes the browser profile: every login and cookie is forgotten.
- Computers stop by themselves after `COMPUTER_IDLE_MINUTES` (10) without a task.
- Kill switch: `PRISM_V24_ENABLED=false` and restart. v2.3 QA keeps working; no new computer tasks start.
- If a test stays at zero steps before an engine run is assigned, the panel shows
  **Waiting for workspace** and explains that testing has not started. Check the swarm API
  and worker. A listening port alone does not prove API health: a stale Uvicorn reloader
  can hold port 8080 after its server child has exited. Restore that API process; the
  configured watcher reconciles the original approved start using its operation keys.

## Website testing: automatic page discovery

New website test plans default to **Discover pages automatically**. For example, say
“Test https://example.com” to a QA Prism. Routes are optional starting pages, not a required
list. The Prism explores visible links, menus and client-side routes, records checks as it
works, and reports tested pages, issues and discovered pages left untested with reasons.
User-defined restrictions still apply. Existing saved plans keep their original scope;
send a new request to use discovery.

- The initial HTTP(S) origin is the boundary. Subdomains, different ports and other sites
  need a separate site-access approval. Approval is kept on this run's continuation chain,
  not added permanently to a shared target. A login approval cannot silently authorize a host.
- Authentication uses the existing secure login card and stored-login tool. Credentials
  stay outside the model context. Declined logins leave authenticated pages blocked.
- Low-risk forms can use clearly synthetic values such as `Prism QA Test` and
  `prism-qa@example.invalid`. A generic Submit exception requires a fully synthetic,
  recognizably low-risk form. Payments, messages, deletions, publishing, account creation
  and other important changes still require approval, even with dummy values. Ambiguous
  actions remain approval-gated. Browser label checks remain best effort; this is not a
  general transaction firewall.
- The engine pauses before another model call near the approved turn/cost limit. The card
  shows new **total** limits. **Extend and continue** resumes from completed tool results;
  **Finish with partial report** stops without queuing more work. Ordinary action/login
  approvals do not refill the budget. Extensions remain bounded by Prism's configured QA
  caps and the engine's hard ceilings. Model-call cost is known after the response, so one
  response can consume the remaining estimate; no further tool from an over-budget reply runs.
- Coverage comes from browser snapshots and recorded test results. Visiting a page alone
  does not count as testing it. Tracking links and anchors are deduplicated; SPA hash routes
  are retained. Discovery tracks at most 200 routes and five query variants per path to
  bound crawl traps. Hitting these bounds, blocked pages or unfinished work produces a
  partial-coverage report. Hard worker timeouts, cancellation, CAPTCHA and crashes can also
  end a run with partial results; no claim of exhaustive coverage is made.

Restart **both the swarm API and worker**, then Prism, after applying these changes. No new
database migration is needed: the policy, coverage and continuation data use existing JSON
fields. Verification uses synthetic providers/browser responses, disposable PostgreSQL and
the real Chrome UI; it does not test forms on a live customer website.

## Safety, in one place
- Outward actions wait through `confirm_action`, `request_login` and `ask_manager`; browser click, form submission and Enter/Return paths are guarded for send / post / submit / pay / delete intent. The check is conservative semantic policy, not a guarantee about arbitrary page JavaScript.
- Logins are typed into Prism's secure card, stored encrypted in the engine, typed into the site by the worker, and masked from every event. Prism keeps only the site and a masked username.
- Public-site computers resolve traffic through an in-container proxy that blocks loopback, private, link-local, metadata and mixed private/public DNS answers. `COMPUTER_ALLOW_LOCAL_SITES=true` disables that boundary and is development-only.
- Limits are clamped on the server: `WORK_MAX_TURNS_CAP`, `WORK_BUDGET_CAP_USD`, `WORK_MAX_MINUTES`.

## Recovery contract

- Workers lease and fence runs. Completed tool boundaries are checkpointed for the streaming OpenAI Agents runtime; an expired safe run is requeued from its last checkpoint.
- A crash during a potentially outward action ends as `outcome_unknown`. It is never replayed automatically; inspect the target site, then start a deliberate new task if appropriate.
- Prism task/run/approval calls use stable operation keys, so retrying after a lost HTTP response returns the existing engine operation instead of creating a duplicate.
- Approval expiry rejects pending approvals and returns the task to `todo`. Restart recovery is periodic, not only a startup action.

## Known limits
CAPTCHAs, one-time codes and sites that block bots stop a Prism (no take-control yet). Docker's socket is not mounted anywhere; the worker runs on the host. A live provider/container worker-kill drill is still required before treating checkpoint recovery as deployment-proven.

## AI spend: Prism vs agent swarm

- Two columns (Overview, Settings > Usage and spend): `provider = qa_workspace` rows are the swarm, everything else is Prism. Days follow `MANAGER_TIMEZONE`; INR is the default display currency.
- Cost = exact input / cached-input / output tokens x the model's rate in `LLM_MODEL_PRICING` (Prism `.env`, one entry per deployment either project uses). The swarm keeps its own rate card in `AZURE_MODEL_PRICING` (swarm `.env`) so its live per-run budget matches.
- Add a new deployment: add it to both lists, otherwise its calls show as "unpriced".
- Changing a rate or the pricing rule: bump `LEDGER_VERSION` in `qa_spend_service.py`; the next sync re-prices every swarm row.
- Azure billed total (optional): set `AZURE_BILLING_*` (see `.env.example`). Azure posts charges hours late, so today reads lower than the estimate. Not verified against a live tenant.

## Live screen

- Each computer runs one Chromium (headless, DevTools on 9222) that both the agent (Playwright MCP, `--cdp-endpoint`) and a small streamer (`app/computers/guest/stream.mjs` in the swarm repo) attach to. The streamer serves multipart JPEG on port 8932, published on localhost only. While watched, periodic captures target eight fresh frames per second alongside Chromium's screencast events (capped around 15 fps); actual speed depends on the computer and connection. Captures continue through navigation and idle pages rather than depending on saved task screenshots.
- The open panel and enlarged view share one stream. The panel labels a decoded feed as live, reports reconnects, and labels the final image as the last screen after the task ends. A stream with no data for ten seconds reconnects automatically. The feed shows browser activity; reasoning and API calls do not themselves change the browser screen.
- Path: browser -> swarm `GET /api/v1/computers/{key}/stream` -> Prism `GET /api/v2/prisms/{id}/computer/live` -> sidebar and the enlarge popup. Watch only; nothing the viewer does reaches the computer.
- A cursor and click ripple are drawn on the page itself (the agent drives Chromium over DevTools, so no real pointer exists). They show in live view and in saved screenshots.
- Changing `guest/` or the launch options: bump `SPEC_VERSION` in `app/computers/manager.py`; computers are recreated on next use, logins are kept.
- Known limit: `--allowed-origins` is exact. A task on `wikipedia.org` is blocked on `en.wikipedia.org`, and `example.com` blocked on its `iana.org` link.
