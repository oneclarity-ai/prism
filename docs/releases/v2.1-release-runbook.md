# Prism v2.1 local release runbook

Prism v2.1 is a manager-only web agent. You keep one continuing conversation with Prism, ask for an
outcome, and Prism resolves, reads, and discloses the relevant authorized Teams chats. It explains
what needs attention with message-level evidence and prepares one or more drafts. You edit,
approve, or reject each draft, and Prism sends only the exact approved text through delegated
Microsoft Graph as the connected manager. Model output cannot send directly. Teams people and
groups are sources and destinations, not separate Prism chats.

## Required configuration

Use Python 3.11+, PostgreSQL 14+, and the normal Microsoft delegated OAuth setup in the main
README. Set `PRISM_V21_ENABLED=true`, configure one supported local model provider, and run:

```bash
make setup
make migrate
make check
make dev
```

Codex authentication from `~/.codex/auth.json` is a development-only provider option. Do not copy
that file into the repository or use it as a deployment credential. OpenAI BYOK values entered in
Settings are encrypted in PostgreSQL and are never returned to the browser.

## Microsoft permissions

The delegated connection needs the permissions documented in the main README, including Teams
chat read/write access. A public tunnel is not required for the v2.1 on-demand read/review/send
flow. A public HTTPS webhook URL is required only for the legacy background notification flow.
Reading a chat never authorizes writing to it; each destination is explicit on its own approval
card.

## Using the Agent workspace

1. Open **Agent**. There is one conversation; start with a natural request. No chat needs to be
   chosen first.
2. Check the **Read from** chips and **Why these sources** on the answer. Prism names the chats it
   read and why, and shows the limits it applied.
3. The source filter defaults to **Auto**. Choose a chat from it only to limit later requests, and
   choose **Auto** again to remove the limit. Saying "only check my chat with Parv" in a request
   also works.
4. If a name is ambiguous, Prism asks which chat you meant before it reads anything.
5. Open evidence to see the sender, time, and excerpt behind each claim.
6. A drafting request produces one card per destination. Edit the text, **Save edit**, then
   **Approve and send**. Approving one card never approves another. **Approve all** appears only
   while every exact text is visible and saved.
7. Use **Search** to find earlier messages and jump into history, and **Load earlier messages** for
   older turns. Past topics stay in the same conversation.

## Safe live test

1. Use a dedicated development tenant or a Teams chat with yourself.
2. Connect Microsoft and confirm the displayed account is yours.
3. Ask Prism to review only the test chat and inspect every evidence citation.
4. Ask it to draft a message to the test chat, then edit the draft to an unmistakable test message.
5. Click **Approve and send** once.
6. Confirm Teams shows the message from your account and Prism shows `Sent` after refresh.
7. Repeated execution requests must return the stored result and must not create another message.
8. For a coordinated plan, repeat with two self-directed or dedicated test chats. Approve one card
   and reject the other, and confirm exactly one message was delivered.

## Recovery and failure modes

- `queued`: **Resume** safely repeats read/review work.
- `researching` or `planning` after interruption: recovery marks the job failed; **Retry** creates
  a new job.
- `waiting_for_approval`: refresh restores the same drafts and no action occurs without approval.
- `executing` after interruption: **Check interrupted delivery** marks the result uncertain and
  never replays the write. Manually inspect Teams before creating a new draft.
- `reconciliation_required`: Prism could not prove whether Microsoft accepted the request and
  deliberately does not retry. The card says delivery needs your confirmation.
- Microsoft reconnect required: the notice offers **Reconnect Microsoft**. Nothing was sent.
- Microsoft permission missing: ask an admin to grant Teams chat access, then reconnect. Nothing
  was sent.
- Microsoft throttling: wait a minute and ask again. Your text stays in the composer.
- In a coordinated plan, a failed or uncertain action blocks only the actions that depend on it.
  Successful actions are never replayed.

## Database backup and restore

Back up before migration or a live test:

```bash
pg_dump --format=custom --file=prism-backup.dump yash_manager_db
```

Restore into a separate empty database first:

```bash
createdb prism_restore_check
pg_restore --no-owner --dbname=prism_restore_check prism-backup.dump
```

The relevant durable audit tables include `agent_threads`, `agent_thread_aliases`,
`agent_thread_messages`, `agent_jobs`, `agent_job_sources`, `agent_source_messages`,
`agent_conversation_reviews`, `action_proposals`, `approval_decisions`, `tool_executions`,
`agent_preferences`, and `agent_feedback_events`. The encrypted Microsoft and provider credentials
also depend on keeping the same local encryption key.

## Release gate

Run these in order. All use fake Graph and model providers and must not make live POST requests.

| Gate | Command | Notes |
| --- | --- | --- |
| Lint, format, types, unit tests, secret scan | `make check` | Runs without PostgreSQL. |
| PostgreSQL integration, including migration and rollback | `make test-integration` | Uses the database in `.env`; tests clean up their rows. The migration test runs in a private schema. |
| Browser journeys at desktop and phone width | `make test-e2e` | Needs Google Chrome. Runs on the throwaway `prism_e2e` schema with every credential blanked. |
| Dependency audit | `make audit` | Review any finding before release. |

The browser suite covers the full journey: ask without choosing a chat, inspect disclosed sources
and evidence, request two coordinated replies, edit both, approve one, reject one, deliver exactly
once, and verify the audit trail after refresh. It also covers reconnect, permission, throttling,
failed delivery, double-clicking approve, hostile Teams and model text, ambiguous names, search and
history, and horizontal overflow at phone width.

Then complete these by hand, because they need real accounts or assistive technology:

- A keyboard-only pass at desktop and narrow width. Focus must reach the source filter, search,
  evidence, draft editing, each approval card, preferences, recovery actions, and delivery status.
- A screen-reader pass over the composer, the live status region, approval cards, and dialogs.
- One controlled real-provider and real-Microsoft run from the Agent workspace, following the safe
  live test above.
- Regenerate screenshots with `E2E_SCREENSHOTS=1 make test-e2e` if the interface changed.

Prism remains pre-release and has not received an independent security audit. Do not treat the
automated test suite as an independent security assessment.
