## One complete workflow traced through code

1. **Create and onboard.** `/api/v2/prisms` creates a draft (`app/api/routes/prism_v22.py`, `prism_lifecycle_service.py`). Onboarding questions and answers live in `prism_onboarding_`*; `prism_agreement_service.py` constructs and confirms the agreement. `prism_profile_service.py` stores capabilities, login policy and role instructions. Brain context is selected by `prism_agent_service.py` when the engine agent is built.
2. **Plan and start.** A chat web task reaches `QaRunService._handle_work_chat`, which stores a `QaRun(kind="work", state="planned")` and a `work_plan` message. The manager starts it through the existing `/api/v2/qa/runs/{id}/start` route. `QaRunService.start` applies edits, commits `starting`, calls `PrismAgentService.ensure`, creates an engine task/run and stores engine IDs in `qa_runs`. The separate commits/HTTP calls leave an orphan/unknown-outcome window on crash or timeout.
3. **Execute.** Swarm `services/runs.py` queues a run; `worker/executor.py` claims with `FOR UPDATE SKIP LOCKED`, constructs grants and context, and `runtime/openai_agents.py` uses a per-agent computer. `ComputerManager` keeps its profile volume; the runtime writes events, frames, checklist and results. The worker's one-at-a-time check is by agent ID, which works for the usual one-agent-per-Prism mapping but is not a computer-key lock.
4. **Pause and resume.** SDK approval interrupts are saved in swarm `runs.saved_state`; Prism's watcher (`QaRunService.cycle/sync`) relays them into chat. `QaRunService.decide` sends the decision to swarm and stores the new resume-run ID. Swarm creates a **new** queued run using saved state and approved decisions. The secure card writes the secret before the decision; a crash between those operations can leave a stored login and a pending card. Repeated approval is guarded per approval row, but there is no cross-service transaction.
5. **Report and persist.** Swarm finalizes result/artifacts; Prism's watcher advances `last_event_seq`, builds a work or QA report, posts a chat message and saves the report on `qa_runs`. Operational proof of a full custom journey, including real browser, approval and report, remains pending.

## Critical-gap implementation status

1. **P0 crash and ambiguous execution — fixed in code/tests.** Leased claims, periodic renewal,

   fencing tokens, tool-boundary checkpoints and stale-run recovery replace fail-all startup
     recovery. Safe checkpoints resume; risky in-flight actions become `outcome_unknown`, update the
     parent task, and are not retried.
2. **P0 browser and credential boundaries — fixed in code/tests.** Public browsers use the

   resolving deny proxy, outward guards cover click/form/Enter paths, and per-Prism credentials
     stay behind `sign_in`. The development-only local-site bypass defaults off.
3. **P1 cross-service lifecycle — fixed in code/tests.** Stable Prism operation keys deduplicate

   task/run/decision writes. `starting` remains reconcilable and watcher outages no longer create a
     false terminal result.
4. **P1 visibility — materially fixed; retention review remains.** Prism shows a safe, explicit

   uncertain-action warning. Immediate agent-spec push is still not required for execution safety;
     `ensure` refreshes it before the next task. Screenshot/artifact retention remains an operational
     policy item, not a blocker to recovery.
5. **P2 end-to-end proof — automated cross-repo suites pass; live drill remains.** The disposable

   PostgreSQL/fake-engine suites cover the contracts. A real Docker/browser worker-kill drill and
     live provider checkpoint resume must still be recorded before calling the deployment proven.

### Independently testable definition of done for the next milestone

- A custom Prism is created, onboarded, confirmed, given a browser-only task, shown a plan, started, paused for a question/login/action and resumed to one persisted report via existing UI/API paths.
- A replacement worker resumes completed read-only steps after a forced kill. It neither repeats an already recorded step nor claims a live worker's lease. An interrupted outward step is marked unknown and requires human reconciliation; no automatic retry occurs.
- Repeated Start and Approve requests, including lost responses after engine commit, converge to one engine task/run or approval resume, one Prism run and one terminal chat report.
- Per-Prism profiles and credentials remain isolated. A submitted card is recognized on resume; no password appears in model input, events, logs, Prism transcript, SSE or downloadable artifacts. Browser access to private/metadata addresses is denied in public-site mode.
- All existing QA/Teams/Brain behavior, approval contracts and v2.4-off behavior pass their targeted regressions. Tests use disposable data; real Docker/browser and crash drills are recorded separately from fake-engine test results.
