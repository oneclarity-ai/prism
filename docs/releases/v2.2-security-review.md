# Prism v2.2 security review

Scope: the v2.2 routes under `/api/v2/prisms`, their services, and the browser code. Each row names
the control and the automated test that proves it (PostgreSQL tests need `RUN_DB_TESTS=1`).

| Risk | Control | Proof |
| --- | --- | --- |
| Cross-Prism access (IDOR) | Every service resolves the Prism first and checks `observation.prism_id`; a foreign id returns 404. The browser never supplies a thread id. | `test_cross_prism_ids_are_refused_and_everything_needs_the_operator_token`, `test_prism_conversation_integration` |
| Operator-token bypass | All `/api/` routes pass the operator-token middleware; the sweep fails if any v2.2 route answers without it. | same test, `test_security.py` |
| Approval bypass | No route, schedule, event, notification, or model output approves or executes. Drafts are `pending` until `/decision` and `/execution` are called by the user; stale drafts expire first. | `test_prism_draft_integration`, v2.1 approval suites |
| Recipient / destination substitution | Destination is the chat where the signal was seen, re-authorized at send time by the v2.1 execution path; payload hash covers destination and text. | v2.1 execution tests |
| Prompt injection | Teams text is evidence only. A draft request contains the user's words and a fixed signal label, never Teams text; evidence cannot change policy or approve an action. | `PrismDraftService.create` |
| XSS | Browser code builds the DOM with `textContent`; no Teams or model text is inserted as HTML. | review of `agent-chat.js`, `prism-updates.js`, `prism-health.js` |
| Secret leakage | Health and metrics return counts and booleans only; notifications carry urgency, signal type, and Prism name, not message text; failed-attempt logs omit prompts. | `test_budgets_circuit_breaker_health_and_no_leaks` |
| Unbounded work | Per-Prism run, model, and failure budgets; bounded polling sources and messages; lease-claimed runs; retention. | `test_prism_operations_integration` |
| Duplicate or replayed alerts | One claim per notification; a per-incident lock and suppression; idempotent draft requests. | notification and incident integration tests |
| Concurrent workers | Per-Prism sync lock, per-incident lock, dedicated advisory-lock connection for the scheduler. | `test_duplicate_incident_alerts_once_and_survives_restart_and_pause` |
| Rollback safety | The v2.2 flag hides routes and keeps records; the migrated thread stays resolvable by v2.1. | `test_turning_v22_off_leaves_v21_usable_and_v22_records_intact` |

Findings fixed during this review: a Teams event key that was unique across Prisms (a second Prism
silently ingested nothing); a scheduler lock that could leak across pooled connections and stall
every run; duplicate events inside one Graph batch aborting a sync. No critical or high-severity
issue remains open. Remaining manual items: a screen-reader and keyboard pass, and the live
Microsoft smoke test.
