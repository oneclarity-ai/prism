# Prism v2.1 Phase 2: durable agent state machine

## Outcome

Prism now has durable, restart-safe records for Agent Chat threads, jobs, progress steps, action
proposal revisions, manager approval decisions, and tool executions. This phase does not read or
write Microsoft Teams; it establishes the control plane that later phases must use.

The local `.env` enables `PRISM_V21_ENABLED=true` so the foundation can be inspected during
development. The committed default remains false.

## Persistence model

- `agent_threads`: manager/Prism conversations and their selected source metadata.
- `agent_jobs`: one goal with an explicit lifecycle and optimistic version.
- `agent_steps`: ordered, visible progress persisted before future external operations.
- `action_proposals`: immutable destination/body revisions with canonical SHA-256 payload hashes.
- `approval_decisions`: the exact revision and hash approved or rejected by the manager.
- `tool_executions`: idempotent read/write attempts and safe delivery results or errors.

Migration `20261028_0019` creates these tables and their PostgreSQL enums.

## State rules

Job and step transitions are allow-listed. Terminal jobs and steps cannot restart silently. Every
job mutation checks an expected version, while approval, revision, and execution paths lock the
authoritative row in PostgreSQL.

Editing a proposal expires the previous revision and creates a new pending row. Existing approval
remains as audit history on the old revision but cannot authorize the new hash. Execution requires
an approved current revision, matching manager identity, revision, and payload hash.

Every proposal has one deterministic execution idempotency key. Repeated or concurrent execution
starts return the existing record after acquiring the proposal lock; they do not create another
intentional external write.

## Stable API contracts

The feature-flagged `/api/v2/agent` API exposes thread, job, step, proposal, approval, execution,
and foundation response schemas. Responses contain display-safe errors and no provider payloads,
tokens, credentials, or stack traces.

The Phase 2 UI deliberately remains small: **Settings → Prism v2.1 agent foundation** shows durable
record counts and can create a harmless queued test job. The complete Agent Chat experience belongs
to Phase 5.

## Completion checks

- [x] Six v2.1 persistence models and migration exist.
- [x] Legal job and step transitions are explicit and tested.
- [x] Proposal revisions bind action, destination, and body through canonical hashes.
- [x] Edits invalidate the previous revision for execution.
- [x] Approval revalidates revision and hash.
- [x] PostgreSQL row locks and optimistic job versions protect races.
- [x] Execution uses a unique idempotency key and authoritative result.
- [x] Stable frontend response schemas and feature-flagged APIs exist.
- [x] A visible persistence smoke test exists in Settings.
- [ ] A separate empty PostgreSQL database has been migrated from base to head.

The existing local database has been upgraded from the pre-v2.1 schema. The separate clean-database
gate remains part of release hardening unless a disposable database is provided for that test.
