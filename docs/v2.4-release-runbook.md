# v2.4 runbook: every Prism has its own computer

## Turn it on
1. Docker Desktop must be running **on the machine that runs the engine's worker**.
2. Engine `.env`: `PRISM_BRIDGE_URL`, `PRISM_BRIDGE_SECRET` (same value as Prism's `WORK_BRIDGE_SECRET`; needed only for Teams tools). Optional: `COMPUTER_IMAGE` (pin a tag).
3. Apply migrations: Prism `make migrate`; engine `.venv/bin/alembic upgrade head`.
4. Restart the engine API **and its worker**, then Prism (`PRISM_V24_ENABLED=true`).
5. `python scripts/prism_admin.py work-check` must print `"ok": true` (engine reachable, a worker online, Docker answering).

## Operate
- `python scripts/prism_admin.py computers list` shows each Prism's computer (missing / stopped / running).
- `computers stop [--key prism-xxxxxxxx]` stops one or all (browser profiles are kept).
- `computers reset [--key ...]` deletes the browser profile: every login and cookie is forgotten.
- Computers stop by themselves after `COMPUTER_IDLE_MINUTES` (10) without a task.
- Kill switch: `PRISM_V24_ENABLED=false` and restart. v2.3 QA keeps working; no new computer tasks start.

## Safety, in one place
- Outward actions always wait: `confirm_action`, `request_login`, `ask_manager`, and clicks whose label says send / post / submit / pay / delete (best effort, label based).
- Logins are typed into Prism's secure card, stored encrypted in the engine, typed into the site by the worker, and masked from every event. Prism keeps only the site and a masked username.
- Limits are clamped on the server: `WORK_MAX_TURNS_CAP`, `WORK_BUDGET_CAP_USD`, `WORK_MAX_MINUTES`.

## Known limits
CAPTCHAs, one-time codes and sites that block bots stop a Prism (no take-control yet). Docker's socket is not mounted anywhere; the worker runs on the host.

## AI spend: Prism vs agent swarm

- Two columns (Overview, Settings > Usage and spend): `provider = qa_workspace` rows are the swarm, everything else is Prism. Days follow `MANAGER_TIMEZONE`; INR is the default display currency.
- Cost = exact input / cached-input / output tokens x the model's rate in `LLM_MODEL_PRICING` (Prism `.env`, one entry per deployment either project uses). The swarm keeps its own rate card in `AZURE_MODEL_PRICING` (swarm `.env`) so its live per-run budget matches.
- Add a new deployment: add it to both lists, otherwise its calls show as "unpriced".
- Changing a rate or the pricing rule: bump `LEDGER_VERSION` in `qa_spend_service.py`; the next sync re-prices every swarm row.
- Azure billed total (optional): set `AZURE_BILLING_*` (see `.env.example`). Azure posts charges hours late, so today reads lower than the estimate. Not verified against a live tenant.

## Live screen

- Each computer runs one Chromium (headless, DevTools on 9222) that both the agent (Playwright MCP, `--cdp-endpoint`) and a small streamer (`app/computers/guest/stream.mjs` in the swarm repo) attach to. The streamer serves multipart JPEG at about 15 fps on port 8932, published on localhost only.
- Path: browser -> swarm `GET /api/v1/computers/{key}/stream` -> Prism `GET /api/v2/prisms/{id}/computer/live` -> sidebar and the enlarge popup. Watch only; nothing the viewer does reaches the computer.
- A cursor and click ripple are drawn on the page itself (the agent drives Chromium over DevTools, so no real pointer exists). They show in live view and in saved screenshots.
- Changing `guest/` or the launch options: bump `SPEC_VERSION` in `app/computers/manager.py`; computers are recreated on next use, logins are kept.
- Known limit: `--allowed-origins` is exact. A task on `wikipedia.org` is blocked on `en.wikipedia.org`, and `example.com` blocked on its `iana.org` link.
