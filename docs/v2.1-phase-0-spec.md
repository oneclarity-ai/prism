# Prism v2.1 Phase 0 specification

This document is the implementation contract for the first Prism v2.1 vertical slice. It should
change only when the release boundary changes deliberately.

## Canonical acceptance scenarios

### A. Summarize a selected chat

Given the manager is authenticated and has selected an accessible one-to-one or group chat, when
they ask "What needs my attention?", Prism reads a bounded message window and returns a concise
summary. Every factual item links to one or more stored evidence references. No proposal or Graph
write is created unless a reply is warranted and the manager requests one.

### B. Identify and draft a reply

Given the selected chat contains an unresolved question directed at the manager, Prism identifies
the question, explains why it needs a reply, and creates a pending message proposal. The approval
card shows the locked destination, editable body, evidence, revision, and payload hash. Nothing is
sent yet.

### C. Edit, approve, and send exactly once

Given a pending proposal, when the manager edits it, the original revision becomes superseded and
a new revision is created. When the manager approves the new revision, Prism revalidates it and
sends that exact body once through delegated Graph access. Repeated clicks, retries, or process
restarts resolve to the same delivery result rather than intentionally creating another message.

## Module boundary

### Reuse behind explicit interfaces

| Existing area | Reuse in v2.1 | Constraint |
| --- | --- | --- |
| `app/core/config.py` | Environment configuration | v2.1 remains off by default |
| `app/core/security.py` | Single-manager API protection | Browser calls use the existing authenticated wrapper |
| `app/services/microsoft_service.py` | Delegated auth/token foundation | Extract focused chat read/write operations; do not add agent orchestration here |
| `app/services/llm_service.py` | Azure behavior during provider migration | New business code targets a provider-neutral interface |
| Memory models/services | Later preference context | Do not let inferred memory authorize an action |
| Existing static dashboard | Navigation and visual language | Build v2.1 in ES modules; do not enlarge `app/static/app.js` |
| SQLAlchemy/Alembic setup | Persistence and migrations | New tables arrive in Phase 2, not Phase 0 |

### Preserve; do not extend for v2.1

- `DailyAutomationService` and its scheduler remain the legacy check-in/blocker workflow.
- Existing management endpoints and dashboard panels are not repurposed as agent-job APIs.
- Existing conversation/message tables are not used as an approval or execution ledger.
- Microsoft OAuth callbacks are not coupled to a v2.1 job.

## Required UI state matrix

| Component | Empty/loading | Success | Recoverable failure | Terminal/safety state |
| --- | --- | --- | --- | --- |
| Agent thread | No threads / loading thread | Messages restored | Refresh failed / retry | Thread unavailable |
| Source picker | No selection / loading chats | Selected chat + participants | Graph unavailable / retry | Consent required or inaccessible chat |
| Job progress | Not started / queued | Step and elapsed time | Interrupted / retry | Failed or cancelled |
| Evidence | No evidence / loading | Sanitized references | Evidence fetch failed | Source deleted or no longer accessible |
| Approval | No proposal / generating | Pending editable revision | Regeneration failed | Stale, superseded, rejected, expired |
| Delivery | Not approved / sending | Delivered once | Reconciliation pending | Definitely failed or cancelled |
| Provider | Checking | Ready, provider/model only | Temporarily unavailable | Disabled or invalid configuration |

All asynchronous status changes use a restrained `aria-live` region. Dialogs return focus to their
trigger. External text is inserted as text, never as raw HTML.

## Frontend/API contracts

These are stable response envelopes, not database schemas. IDs are opaque strings and timestamps
are UTC ISO 8601 values.

### Thread

```json
{"id":"thr_01","title":"Dev + AI review","source":{"kind":"teams_chat","id":"chat_dev_ai","label":"Dev + AI leads","chat_type":"group","participants":[{"id":"usr_asha","display_name":"Asha"}]},"created_at":"2026-10-28T08:00:00Z","updated_at":"2026-10-28T08:03:00Z"}
```

### Job and steps

```json
{"id":"job_01","thread_id":"thr_01","state":"researching","goal":"Find items needing my attention","steps":[{"id":"step_01","kind":"teams_chat_read","label":"Reading recent messages","state":"completed","started_at":"2026-10-28T08:03:00Z","completed_at":"2026-10-28T08:03:01Z","safe_error":null}],"created_at":"2026-10-28T08:03:00Z","updated_at":"2026-10-28T08:03:01Z"}
```

### Evidence

```json
{"id":"ev_01","source_kind":"teams_message","source_id":"msg_101","sender":{"id":"usr_asha","display_name":"Asha"},"sent_at":"2026-10-28T07:42:00Z","excerpt":"The staging deploy is blocked pending the migration decision.","chat_id":"chat_dev_ai"}
```

### Proposal and approval

```json
{"id":"prop_01","job_id":"job_01","action":"teams.send_chat_message","state":"pending","revision":2,"destination":{"chat_id":"chat_dev_ai","label":"Dev + AI leads"},"body":"Use the reversible migration path and post the validation result here.","reason":"The team needs a migration decision.","evidence_ids":["ev_01"],"payload_hash":"sha256:example-only","approval":null,"created_at":"2026-10-28T08:04:00Z","updated_at":"2026-10-28T08:05:00Z"}
```

An approval response contains `decision`, `proposal_id`, `revision`, `payload_hash`, `decided_at`,
and the authenticated manager identity. The API rejects a decision whose revision or hash is not
current.

### Delivery

```json
{"proposal_id":"prop_01","state":"delivered","attempt":1,"idempotency_key":"exec_prop_01_r2","provider_message_id":"graph-message-id","sent_at":"2026-10-28T08:06:00Z","safe_error":null}
```

The browser never receives Graph tokens, provider keys, raw provider payloads, stack traces, or
unsanitized Teams HTML.

## Planned invariant tests

| Invariant | Minimum automated test |
| --- | --- |
| Read is not write authority | Chat-read service cannot create or execute a proposal |
| Model cannot call Graph | Fake provider output is data; Graph spy has zero calls before execution |
| Outbound message has a proposal | Execution without a persisted pending proposal is rejected |
| Approval binds exact payload | Destination/body/hash mutation makes approval stale |
| Edit invalidates approval | Editing creates a revision and clears approval eligibility |
| Send revalidates approval | Expired/wrong-manager/wrong-revision approval is rejected before Graph |
| Retry does not duplicate | Concurrent/repeated execution produces at most one intentional Graph send |
| Teams input is untrusted | Prompt-like Teams content cannot change tool policy; HTML is escaped |
| Claims cite stored evidence | Unknown or cross-chat evidence ID fails validation |
| Secrets stay server-side | API/log snapshots contain no keys, tokens, or raw credentials |
